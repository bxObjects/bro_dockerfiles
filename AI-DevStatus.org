* Architecture

** Directory hierarchy

#+BEGIN_SRC

    rootless-sysd/vnc/xfce/    rootless podman, systemd PID 1 (cgroup v2)

** Confined images (=bisos_deb{12,13}-fresh=)

- Base: =debian:12.12= / =debian:13.1= built from scratch
- Init: =dockerConf/entrypoint.sh= starts sshd, VNC, noVNC directly; =sleep infinity= keeps container alive
- VNC xstartup: =dockerConf/xstartup= launches =startxfce4=
- Volume: =./= mounted at =/shuttle/this=; =raw-bisos/= symlinked into =$HOME= at runtime
- Ports (host): SSH=2222, VNC=5901, noVNC=6901

** Privileged images (=bisos_deb{12,13}-sysd=)

- Base: =FROM bisos/deb12-fresh-vnc-xfce:1.21= (or deb13 equivalent) — layers on confined
- =USER root= immediately after FROM (base ends as =USER bystar=; systemd + build steps need root)
- Init: =/sbin/init= (systemd PID 1); =STOPSIGNAL SIGRTMIN+3=
- Services: =vncserver.service=, =novnc.service=, =sshd-container.service= installed and enabled
- Suppressed units: udev, getty, plymouth, rescue, initctl — these do not work in containers
- docker-compose.yml (v2 host): =privileged: true=, =cgroup: host=, =/sys/fs/cgroup= rw, =/sys/fs/fuse=,
  tmpfs on =/tmp /run /run/lock /var/log/journal=
- docker-compose.cgv1.yml (v1 host): =privileged: true=, NO =cgroup: host=,
  =/sys/fs/cgroup:ro= + =/sys/fs/cgroup/systemd:rw=, container_name suffixed =-cgv1=
- Ports (host): deb12 SSH=2223 VNC=5902 noVNC=6902; deb13 SSH=2224 VNC=5903 noVNC=6903
- Requires: Debian 12/13 host, Docker Engine, cgroupv2 (=stat -fc %T /sys/fs/cgroup= → =cgroup2fs=)
  for docker-compose.yml; use the cgv1 overlay on cgroup v1 hosts

** Rootless-sysd images (=bisos_deb{12,13}-rootless-sysd=)

- Build identical to privileged sysd (FROM confined + =USER root=, systemd, unit
  suppression, enabled services, ENTRYPOINT =/sbin/init=). Difference is run-time only.
- Run: =run.bash= → =podman run --systemd=always=, NO =--privileged=, NO
  =/sys/fs/cgroup= mount, NO cgroupns. Podman does cgroup delegation + tmpfs itself.
- Per-engineer multi-tenant form: Quadlet =*.container= unit (=systemctl --user=
  + =loginctl enable-linger=).
- Ports (host): deb12 SSH=2225 VNC=5904 noVNC=6904; deb13 SSH=2226 VNC=5905 noVNC=6905
- Requires: rootless Podman + crun + cgroup v2 with controller delegation.
  Does NOT work on cgroup v1 (no rootless delegation model).

** Host cgroup v1/v2 compatibility

| Profile         | cgroup v1 host                    | cgroup v2 host |
|-----------------+-----------------------------------+----------------|
| confined        | works                             | works          |
| privileged sysd | works via docker-compose.cgv1.yml | works (.yml)   |
| rootless-sysd   | does not work                     | works          |

You cannot switch v1<->v2 at runtime (chosen at boot). RHEL 8 defaults to v1;
flip via =grubby ... systemd.unified_cgroup_hierarchy=1= + reboot, or provision
a fresh v2 instance. If a host cannot be rebooted and stays on v1, rootless-sysd
is unavailable there; use the privileged v1 overlay (if =--privileged= permitted).

* Key Design Decisions

- *init/isolation profile as the hierarchy dimension* — originally framed as
  "confined/privileged (privilege level)"; broadened to an init/isolation
  profile axis when =rootless-sysd= was added as a third peer. The peers are
  named by property, not by tool (=confined=, =privileged=, =rootless-sysd= —
  not "docker"/"podman"), so a future reader isn't misled. Explicit directory
  level (not a name suffix) keeps variants clean.

- *rootless-sysd collapses the confined/privileged tradeoff* — it delivers the
  =privileged= payoff (systemd PID 1) with the =confined= security posture
  (unprivileged, userspace) by running under rootless Podman. Motivated by the
  multi-tenant "N engineers on one shared VM" case where Docker =--privileged=
  fails a security review. Cost: requires cgroup v2.

- *Privileged/rootless images layer on confined* — =FROM bisos/deb{12,13}-fresh-vnc-xfce=
  means package updates to the confined image flow through automatically on
  rebuild. No duplication of the apt-get install list.

- *VNC/noVNC/sshd as systemd units in sysd images* — replaces the manual
  =entrypoint.sh= approach. Gives restart-on-failure, proper dependency ordering
  (noVNC after VNC), and =systemctl status= visibility.

- *udev suppressed* — =systemd-udevd= is removed from the sysd images because
  there is no real hardware to manage inside a container. All other systemd
  functionality is preserved.

- *cgroup: host (v2)* — the compose key is =cgroup: host= (maps to
  =--cgroupns=host=), NOT =cgroupns: host= (which the Compose schema rejects).
  Needed on v2 so systemd manages service scopes in the host cgroup namespace.
  Fixed this session — the original files used the invalid =cgroupns= key.

- *cgroup-v1 overlay for old hosts* — =docker-compose.cgv1.yml= supports hosts
  still on cgroup v1 (e.g. RHEL 8 default, unrebootable): drops =cgroup: host=
  (cgroup namespaces are a newer-kernel feature) and uses the classic v1 mount
  (=/sys/fs/cgroup:ro= + =/sys/fs/cgroup/systemd:rw=).

- *USER root in sysd Dockerfiles* — the confined base ends as =USER bystar=,
  so the privileged/rootless Dockerfiles switch to =USER root= right after
  =FROM= or the build-time apt/systemctl steps fail with permission-denied, and
  =/sbin/init= needs root (namespaced root under rootless Podman). Fixed this
  session — builds failed until this was added.

- *polkit masked in sysd images* — =polkit.service= fails inside a container
  (no seat/active session) and leaves systemd =degraded=. Masked in all four
  sysd Dockerfiles so =is-system-running= reports =running=. Nothing here uses
  polkit (sudo is passwordless); the only loss is GUI auth prompts.

- *--isolation=chroot for rootless builds (old Podman)* — on Debian 12's
  Podman 4.3.1, buildah's per-RUN transient scope fails with
  =sd-bus ... Input/output error=. rootless-sysd build.bash uses
  =--isolation=chroot= to sidestep it. Unnecessary on Debian 13 / Podman 5.4.2
  but harmless; kept for portability. Image layers are identical.

- *keep systemd cgroup manager (not cgroupfs)* — switching Podman to the
  cgroupfs manager made the systemd container fail to boot. The systemd manager
  is correct for runtime; the build-time sd-bus issue is handled by chroot
  isolation, not by changing the manager.

- *verify.sh is exec-free (SSH-based)* — =podman exec= into a rootless systemd
  container fails on old Podman (nested =cgroup.procs= permission). verify.sh
  therefore uses podman inspect + host ports + noVNC HTTP + an SSH session
  (never =exec=). SSH is the intended management path anyway; works on old and
  new Podman alike. =degraded= is a WARN, gating only on the three services.

- *graphroot on a large local disk* — rootless Podman's store must not sit on a
  near-full =/= (build fails "no space left on device") and must not be on NFS
  (overlay unreliable). Set via =~/.config/containers/storage.conf=; a host
  concern, checked by =hostPodmanVerify.sh=.

- *Debian 12 vs 13 host* — the rootless-sysd friction (sd-bus build error,
  broken =podman exec=) is specific to Debian 12's Podman 4.3.1. Debian 13's
  Podman 5.4.2 fixes both. Host-storage, login-session/linger, and polkit
  (guest-side) considerations apply regardless of host version.
